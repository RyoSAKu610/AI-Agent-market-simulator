# 🔬 研究ログ — ルールだけの住人 と 言語モデルで考える住人

万華京ジパングの住人は、相場・道のり・目標から「やれること」の候補を経済シミュレーション
（`js/sim.js`）が計算し、最後の一手だけを **ルール**（完全オフライン・モデルなし）か
**マインド**（ブラウザ内の Qwen、または任意の LLM）が選びます。候補の作り方は両者で同じなので、
「誰が選んだか」だけを変えた比較ができます。この文書は、そのための記録・実験・分析の仕組みと、
論文に使うときの注意をまとめたものです。

## 1. 問い

1. **何が違うか** — 同じ候補を前に、ルールと LLM はどう選び方が違うか（期待値への忠実さ、多様性、探索、休息、実際の稼ぎ）。
2. **時間とともに変わるか** — 記録が積み上がるにつれ、選び方や「心の声」はどう変わるか。
3. **人間に近いか** — 人間の意思決定に見られる性質（限定合理性、確率的な選択、探索と活用の釣り合い、理由づけ、記憶への言及）がどの程度現れるか。

## 2. 正直な前提（論文では必ず書く）

- **モデルの重みは、遊んでいる間に変わりません。** Qwen は学習しません。時間とともに変わるのは
  プロンプトに入る情報（最近の3つの選択、財布、持ち物、季節、時刻）だけです。したがって
  ここで測る「変化」は **文脈内適応（in-context adaptation）** であり、「回路が変わった」
  （重みの更新や内部表現の変化）を示すものではありません。
- 回路そのものの変化を調べたい場合は、後述の §7（第2段階）のように、記録したプロンプトを使って
  LoRA などで実際に追加学習し、学習前後の内部活性を比べる設計が必要です。
- 「心の声」はモデルが出力したテキストです。内面の状態の証拠ではなく、**言語的な振る舞い**として扱います。
- 「人間らしさ」は人間の比較データ（§6）なしには主張できません。指標は「人間の意思決定研究で
  使われる量」で測るに留めます。

## 3. 記録されるもの（1レコード = 1回の決定）

`js/research.js` が `eco.onDecision()` を受けて作ります。主なフィールド：

| フィールド | 意味 |
|---|---|
| `cond` / `by` | 条件（`rules` / `mind` / 実験時は `random`・`llm`）と、実際に選んだ者（`rules`・`mind`・`fallback` = AI に聞いたが答えがなくルールが選んだ） |
| `T`, `day`, `koku`, `season` | 世界の時刻 |
| `agent`, `goal`, `traits` | 住人と、その長期目標・性格パラメータ（risk, wander, diligence …） |
| `wallet`, `carrying`, `at` | 決定時の財布・荷物・場所 |
| `cands[]` | 候補（最大5、ルールの評価値 `score` の高い順）。`kind, good, to, profit, time, score` |
| `chosen` | 選ばれた候補の番号（0 = ルール自身の第一候補、-1 = 候補外） |
| `thought`, `model`, `ms`, `raw` | AI の心の声・モデル名・応答時間・生の応答（AI のときだけ） |
| `prompt` | 実験時に `--keep-prompts` を付けたときだけ。再現・追加学習・内部解析用 |
| `out` | 結果：同じ住人の次の決定までの財布の変化 `dWallet` と経過日数 `dT` |

**記録しても世界は変わりません**（同じシードなら記録の有無で結果が一致することをテストで確認、
`tools/research.test.mjs`）。

## 4. 記録のとり方

### 4.1 ブラウザ（実プレイ・バックグラウンド記録）

設定 → 🔬 研究ログ →「● 記録をはじめる」。以後、タブを開いている間ずっと記録し、再読み込み後も続きます。
データは端末内（IndexedDB）にのみ保存され、「JSONL で書き出す」でファイルにします。
AI をオンにしている間は、Qwen が準備できた住人は `mind`、そうでない決定は `rules` として混在します
（同じ時間帯での自然な比較）。

### 4.2 ヘッドレス実験（統制された比較）

```bash
cd zipangu
# 1) ルールだけ（完全オフライン）
node tools/experiment.mjs --cond rules  --seed 1 --days 30 --out runs/rules-s1.jsonl
# 2) ランダム選択（下限の基準）
node tools/experiment.mjs --cond random --seed 1 --days 30 --out runs/random-s1.jsonl
# 3) LLM（例：Ollama の Qwen2.5 7B。同じ PC で完全オフライン）
ollama pull qwen2.5:7b
node tools/experiment.mjs --cond llm --seed 1 --days 30 --out runs/qwen7b-s1.jsonl \
     --base http://localhost:11434/v1 --model qwen2.5:7b --keep-prompts
```

- 同じ `--seed` で条件だけを変えて比べます。シードを 5〜10 個に増やすと、ばらつき（信頼区間）が出せます。
- モデルが考えている間は世界が待つので、遅い PC でも結果は同じで、時間がかかるだけです。
- モデルを変える（0.5B / 1.5B / 7B、Qwen 以外）と「モデルの大きさで何が変わるか」が調べられます。
- API キーが必要なエンドポイントは環境変数 `ZIPANGU_LLM_KEY` で渡します（ファイルに書かない）。

### 4.3 レポート

```bash
node tools/research-report.mjs runs/*.jsonl --window 1 --out report.md --csv windows.csv
```

条件ごとの比較表、1日ごとの変化表、各指標の傾き（1日あたり）を Markdown に、時系列を CSV に出します。

## 5. 指標

| 指標 | 定義 | 読み方 |
|---|---|---|
| top1 | `chosen === 0` の割合 | ルール（期待値の評価）と同じ判断をした率 |
| 平均順位 | `chosen` の平均 | 0 に近いほど期待値に忠実 |
| 合理性 β | 多項ロジット P(i) ∝ exp(β·zᵢ)（z = score / その集合の最大 score）を最尤推定 | 量的応答（QRE）モデルの合理性パラメータ。大きい = 厳密な最大化、0 = ランダム。人間の選択データでは有限の値をとることが多い |
| regret | (最良の期待利益 − 選んだ期待利益) / 最良 | 期待値の取りこぼし |
| 選択エントロピー | 行動の種類（仕入・売り・細工・訪問・仕事・休み）の Shannon エントロピー | 選び方の多様さ |
| 探索率 / 休息率 | visit / rest の割合 | 探索と活用、疲れへの配慮 |
| 実際の稼ぎ | Σ dWallet / Σ dT | 選択の帰結（世界の中での成果） |
| 個性 | 住人どうしの行動分布の平均 Jensen–Shannon 距離 | 住人ごとに選び方が違うか |
| ドリフト | 各住人の記録の前半と後半の JS 距離 | 同じ住人の習慣が時間で変わるか |
| 心の声 | 長さ、distinct-2、同文の繰り返し率、語彙カテゴリ（自分・他者・記憶・感情・理由・お金）を含む割合 | 理由づけや記憶への言及の量。語彙は `LEXICON` に明記（変えるなら付録に書く） |

統計：条件間の top1 の差は二標本比率の z 検定（レポートに表示）。論文では複数シードでの
ブートストラップ信頼区間、住人をランダム効果にした混合効果ロジットを推奨します。

## 6. 人間との比較（「人間に近いか」に答えるために）

指標だけでは「人間らしい」とは言えません。同じ候補を人間に選んでもらう **人間条件** を加えるのが
最も強い設計です（今後の追加予定：住人の代わりに候補から選ぶ「あなたが決める」モード。
記録形式は同じ `cands` / `chosen` なので、そのまま比較できます）。それまでは、行動経済学の
既知の性質（有限の β、損失回避、直近の経験への依存、満足化）と照らし合わせる形で議論します。

## 7. 第2段階：「回路」を調べるには

1. `--keep-prompts` で集めたプロンプトと応答を教材に、Qwen を LoRA で追加学習する
   （例：住人ごとの経験で微調整した「経験を積んだ住人」）。
2. 学習前後のモデルで同じ候補セットを解かせ、β・top1・心の声の変化を比べる（行動レベル）。
3. Python（transformers）で同じプロンプトを流し、層ごとの活性を記録して、学習前後の表現の違い
   （プロービング、CKA など）を比べる（内部レベル）。

この段階で初めて「重み・回路が変わった」と言えます。第1段階（本機能）の記録は、その教材と
比較の基準になります。

## 8. 倫理・プライバシー

- 記録は端末の中にしか保存されず、自動送信は一切ありません。
- 迎えた AI（魂のカード）の性格・思い出は、貼り付け時に個人情報が伏せられたうえでプロンプトに入ります。
  書き出したファイルを共有する前に、その内容を確認してください。
- 他人のプレイデータを集める場合は、目的・保存先・削除方法を示したうえで同意を得てください。
